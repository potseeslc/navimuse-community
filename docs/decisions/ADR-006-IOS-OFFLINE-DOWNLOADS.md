# ADR-006: Account-bound iOS offline downloads

Status: accepted scope under the owner's September 10 request to repair all audited
feedback, including #354. This supersedes the offline exclusion in ADR-003/004
only for the installed iOS app. It does not claim full M8/M9 acceptance or Android
support. The existing Node BFF remains the service/authentication boundary.

## Contract

- An authenticated BFF endpoint issues a 30-day offline access snapshot for the
  verified opaque account/music scope after an upstream authentication check.
  This is a bounded local access window, not a bearer credential for server APIs.
  The native app obtains it itself using first-party WebKit cookies. JavaScript
  cannot manufacture authorization by supplying an account ID or saved snapshot.
- Native application-support storage owns completed media, metadata and optional
  artwork. Use account-scoped filenames generated by the app, atomic manifests,
  file protection after first unlock and backup exclusion. Never store upstream
  credentials, arbitrary URLs or caller-provided filesystem paths.
- Download only authenticated BFF media for the active scope. Validate response
  status/type and size before committing a file. Incomplete files are not playable.
  Explicit queue, progress, retry, cancellation, removal and clear-storage controls
  are required. Default cellular downloads off; retain an explicit device-local
  setting. Enforce a storage budget and a per-track bound, with useful errors.
- Expiry or explicit sign-out locks playback and removes the current account's
  authorization. Account changes stop/cancel stale work and never expose another
  scope's files. An online authorization rejection invalidates offline access.
  Remote revocation cannot be learned while disconnected; the displayed 30-day
  window is the explicit limit. Clock rollback must not extend that window.
- Downloads resolve into the existing native AVPlayer decks and shared application
  queue. They do not create a second player or queue. Preserve seek, queue advance,
  current ownership and lock-screen controls. Never infer that a remote speaker
  stopped merely because the phone is offline; retain known remote ownership.
- Package a version-matched standalone copy of the existing React application for
  cold-start offline access. A native connection failure offers downloaded music;
  the bundled app consumes native-authorized context rather than forging a live
  login. Network-only actions are disabled or clearly unavailable offline. A local
  fallback page does not broaden access to arbitrary web origins or Rust IPC.
- Reconnection revalidates the account before restoring online library access.
  Offline cached files must remain usable across restart within the access window.
  Playback and management must also work when the server cannot be reached.

## Acceptance before the final release

Tests must cover authentication/scope rejection, expiry, account changes, cancelled
or stale completion, partial/error responses, storage bounds, cellular policy,
restart recovery, local media selection and existing queue behavior. Use actual
native local media and a bundled-app cold start with network unavailable. Simulator
and silent fixtures prove mechanics only; physical background/audio/VoiceOver
acceptance remains explicitly recorded for the owner's final TestFlight test.

The implementation must deliver the complete download/management/offline-playback
flow. A preference, browser cache or backend endpoint alone is not completion.
